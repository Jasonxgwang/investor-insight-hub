# Investor Insight Hub 投资观点库设计说明

## 目标

搭建一个可长期维护、无需数据库和服务器的静态投资观点归档站点。站点直接部署到 GitHub Pages，通过 `reports.json` 展示和检索每日生成的雪球与微博大 V 观点 HTML 日报。

## 技术与目录

站点仅使用原生 HTML、CSS 和 JavaScript，不引入构建工具、前端框架、字体服务或第三方 CDN。

```text
Investor Insight Hub/
├─ index.html
├─ style.css
├─ script.js
├─ reports.json
├─ reports/
│  └─ 2026/
│     ├─ 20260727_233314_投资观点与交易动作汇总.html
│     ├─ 20260729_雪球JS评论_大V多空与仓位变化总结.html
│     └─ 20260730_165535_大V多空观点与交易动作总结.html
└─ docs/
   └─ superpowers/
      └─ specs/
```

## 页面结构

首页采用紧凑的资料库布局：顶部品牌栏显示 “Investor Insight Hub 投资观点库”；其下展示累计日报数量、最近更新日期、覆盖股票数和大 V 数量；再下方提供主搜索框和当前筛选条件。主体为左侧年份与行业导航、右侧日报列表。

日报条目展示日期、标题、摘要、来源、行业和标签，并提供“查看报告”按钮。桌面端左侧导航保持可见；移动端导航收进可开合的筛选面板。页面不采用营销式大幅首屏，也不嵌套卡片。

## 数据模型

`reports.json` 是第一版唯一的目录索引。顶层结构如下：

```json
{
  "schemaVersion": 1,
  "site": {
    "name": "Investor Insight Hub 投资观点库"
  },
  "reports": []
}
```

每条日报包含：

- `id`：稳定且唯一的标识，建议使用日期时间与简短英文标识组合。
- `date`：ISO 日期字符串，格式为 `YYYY-MM-DD`。
- `title`：日报标题。
- `summary`：用于列表展示和检索的简要摘要。
- `file`：相对首页的 HTML 文件路径。
- `year`：数值年份，用于快速分类。
- `industries`：行业名称数组。
- `tags`：主题与观点类型标签数组。
- `stocks`：由 `{ "name": string, "code": string }` 构成的数组；代码未知时允许空字符串。
- `influencers`：大 V 名称数组。
- `sources`：例如“雪球”“微博”。
- `featured`：布尔值，预留精选功能。
- `metrics`：对象，预留阅读量、提及次数和排行指标；第一版允许为空对象。

首页只检索 `reports.json` 的结构化字段，不逐份加载日报正文。这样可控制首屏请求数量，并保证未来日报格式变化不会影响检索。

## 数据流与交互

页面初始化时加载一次 `reports.json`，验证顶层结构后标准化各条记录。统计区根据有效记录实时计算日报总数、最新日期、去重股票数量和去重大 V 数量。

日报默认按日期倒序。关键词不区分英文大小写，同时匹配标题、摘要、日期、股票名称、股票代码、大 V、行业、标签和来源。关键词与年份、行业筛选采用交集逻辑。清除筛选后恢复完整列表。

筛选状态同步到 URL 查询参数，预留并支持 `q`、`year`、`industry`、`tag`、`stock` 和 `influencer`。第一版界面直接操作 `q`、`year` 和 `industry`；其余参数用于未来股票页、大 V 页和标签页跳回首页时调用。

## 错误与空状态

- `reports.json` 加载失败时显示可理解的错误信息，并提供重新加载按钮。
- 数据为空时显示资料库尚无日报的空状态。
- 筛选无匹配项时显示当前条件无结果，并提供清除筛选按钮。
- 单条记录字段缺失时使用安全默认值；缺少有效 `file` 的记录不渲染查看按钮。
- 所有动态文本通过 DOM 文本属性写入，避免将索引内容作为 HTML 注入。

## 视觉与无障碍

视觉以白色、深灰和专业蓝为主，少量青绿色表示更新状态。使用系统字体与 CSS，不依赖外部资源。卡片圆角不超过 `8px`，信息密度适合长期查阅。

页面使用语义化 HTML、明确的标题层级、可见键盘焦点、足够的文字对比度和屏幕阅读器状态提示。移动端不得出现横向滚动、按钮文字溢出或筛选面板遮挡正文。

## 扩展边界

`script.js` 将数据加载、标准化、统计、筛选、URL 状态和渲染拆成职责明确的函数。未来可在不修改日报文件的前提下增加：

- 股票详情页；
- 大 V 详情页；
- 标签聚合页；
- 热门排行；
- 每月汇总；
- 分年 JSON 索引。

当日报规模达到数百或上千条并影响加载速度时，可将 `reports.json` 拆为清单文件与分年索引。首页的数据加载接口保持不变，避免重写页面逻辑。

## 首批内容

首批复制用户提供的三份原始 HTML 日报到 `reports/2026/`，保留原文件名与内部样式。根据日报内容为它们整理结构化摘要、行业、股票、大 V、来源和标签；原始文件不做改写。

## 验收标准

1. 使用本地 HTTP 服务或 GitHub Pages 打开首页时，能够加载全部三条日报。
2. 四项统计数据由索引实时计算且结果准确。
3. 可按股票名称、代码、大 V 名称、标签、日期、行业和来源检索。
4. 年份与行业可组合筛选，刷新页面后筛选状态可恢复。
5. 每条日报的查看按钮能打开对应原始 HTML。
6. 数据为空、无结果和 JSON 加载失败均有明确状态。
7. 手机、平板和桌面布局无重叠、溢出和无意义的大块空白。
8. 所有站点资源均为相对路径，可直接部署到 GitHub Pages 的仓库根目录。
