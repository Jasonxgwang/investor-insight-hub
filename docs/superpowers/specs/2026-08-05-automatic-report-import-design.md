# Investor Insight Hub 自动导入机制设计

## 1. 目标

为 Investor Insight Hub 增加可长期维护的日报自动导入机制。日常使用时，维护者只需把新生成的 HTML 日报放入 `Inbox/`，再运行一次 `import_reports.ps1`；系统完成归档、解析、索引、校验和发布准备，日常维护时间控制在一分钟以内。

站点运行时继续保持纯静态：浏览器只加载 HTML、CSS、JavaScript 和 JSON，不需要数据库、应用服务器或后端接口，可直接部署到 GitHub Pages。

## 2. 核心约束

- GitHub Pages 不能在浏览器端枚举服务器目录，因此不能由首页直接扫描 `Reports/`。
- `reports.json` 继续作为首页的唯一日报索引，避免首页逐份下载和解析日报正文。
- HTML 解析发生在本地导入或 GitHub Actions 构建阶段，不发生在用户浏览网站时。
- 自动解析必须使用确定性规则，不依赖外部 AI、付费 API、数据库或网络服务。
- 不把 Cookie、登录凭证、原始社交平台链接正文或其他敏感信息写入索引。
- 任意一份格式异常的 HTML 不得破坏已有索引；失败必须有清晰、脱敏的错误信息。

## 3. 推荐架构

采用“本地一键导入＋GitHub Actions 自动校验”的双保险架构。

### 3.1 本地一键导入

`import_reports.ps1` 是日常主入口，负责：

1. 扫描 `Inbox/*.html`。
2. 调用 `tools/build_reports_index.py --import-inbox`。
3. 从文件名和 HTML 中识别日期，将文件移动到 `Reports/<年份>/`。
4. 扫描全部 `Reports/**/*.html`，重新生成稳定、可重复的 `reports.json`。
5. 运行索引校验和站点测试。
6. 默认只完成本地更新；使用 `-Publish` 时再提交并推送 GitHub，避免脚本在存在无关改动时静默提交。

导入成功后，`Inbox/` 中对应文件被移走。导入失败时，原文件保留在 `Inbox/`，已有 `reports.json` 不变。

### 3.2 GitHub Actions 自动校验

工作流监听以下路径：

- `Reports/**/*.html`
- `tools/build_reports_index.py`
- `data/entities.json`
- 工作流自身

每次推送后，工作流重新生成索引并运行测试：

- 如果生成结果与仓库中的 `reports.json` 一致，直接通过。
- 如果不一致，自动提交更新后的 `reports.json` 到当前默认分支。
- 如果 HTML 无法解析或索引校验失败，工作流失败并保留清晰日志，不发布损坏索引。

GitHub Actions 只是发布前的构建自动化，不是网站运行时后端。

## 4. 目录结构

```text
Investor Insight Hub/
├─ Inbox/                         # 本地待导入日报，Git 只保留说明文件
├─ Reports/
│  ├─ 2026/
│  ├─ 2027/
│  └─ ...                         # 按解析出的年份自动创建
├─ data/
│  └─ entities.json               # 大 V、股票、行业、标签识别词典
├─ tools/
│  └─ build_reports_index.py      # 扫描、解析、校验和生成索引
├─ .github/workflows/
│  └─ update-reports.yml          # 推送后的自动校验与索引更新
├─ import_reports.ps1             # Windows 一键入口
├─ reports.json                   # 首页唯一数据源
├─ index.html
├─ style.css
└─ script.js
```

现有小写 `reports/` 将迁移为大写 `Reports/`。所有索引路径、测试和文档同步修改，确保 GitHub Pages 的大小写敏感路径正确。

## 5. 解析规则

解析器使用分层优先级。显式元数据优先，HTML 语义结构次之，文件名和文本规则作为后备。

### 5.1 可选显式元数据

未来 AI 生成 HTML 时，可在 `<head>` 中加入以下字段：

```html
<meta name="report:date" content="2027-01-05">
<meta name="description" content="本期核心观点摘要。">
<meta name="report:tags" content="多空观点,仓位变化,风险提示">
<meta name="report:industries" content="半导体,有色金属">
<meta name="report:stocks" content="紫金矿业|601899;腾讯控股|00700">
<meta name="report:influencers" content="飞翔芸;挖地瓜的超级鹿鼎公">
```

这些字段不是日常导入的必填项，但存在时覆盖启发式结果，提高准确性。

### 5.2 日期

优先级：

1. `<meta name="report:date">`。
2. 文件名前缀中的 `YYYYMMDD` 或 `YYYY-MM-DD`。
3. `<title>`、`<h1>` 或正文前部出现的完整日期。

无法确定日期时，该文件解析失败并保留在 `Inbox/`，不得使用文件修改时间猜测归档年份。

### 5.3 标题

优先级：

1. `<meta name="report:title">`。
2. `<title>`。
3. 第一个 `<h1>`。
4. 去掉日期、时间和扩展名后的文件名。

展示标题会清理重复日期和多余空白，但保留原中文语义。

### 5.4 摘要

优先级：

1. `<meta name="description">` 或 `<meta name="report:summary">`。
2. “核心结论”“核心观点”“摘要”“市场概览”等标题后的第一组有效段落或列表项。
3. 正文开头第一段具有信息量且不是统计口径、免责声明或生成时间的文字。

摘要清理 HTML 标签和重复空白，最长 180 个中文字符，在完整句号附近截断。无法提取时使用“本期日报已归档，点击查看完整内容。”，同时生成警告。

### 5.5 股票名称与代码

按以下来源合并去重：

1. `report:stocks` 显式元数据。
2. 表格中标题为“标的”“股票”“证券”“代码”的列。
3. 正文中的标准证券代码与邻近名称组合。
4. `data/entities.json` 中股票别名与代码词典的全文匹配。

允许仅识别股票名称而代码为空。禁止把日期、CSS 色值、数量统计或普通六位数字误判为股票代码。

### 5.6 大 V

按以下来源合并去重：

1. `report:influencers` 显式元数据。
2. 表格中“作者”“大 V”“账号”“博主”列。
3. “作者：”“观点人：”等固定文本模式。
4. `data/entities.json` 中固定雪球大 V 与微博账号的全文匹配。

词典支持规范名称与别名，索引只保存规范名称。

### 5.7 标签与行业

- 显式元数据优先。
- 启发式规则只从受控词表中选择，避免每天产生大量近义标签。
- 标签根据标题、章节名、徽标文字和正文关键词打分，例如“买入”“减仓”“仓位变化”“风险提示”“多空分歧”。
- 行业根据已识别股票映射和正文行业关键词打分，例如“半导体”“人工智能”“有色金属”“新能源”。
- 每份日报默认最多 6 个行业和 8 个标签，按得分和固定优先级排序。

## 6. 索引生成

`build_reports_index.py` 每次扫描全部 `Reports/**/*.html`，而不是只追加新记录。这样可以自动处理文件删除、改名、年份迁移和解析规则升级。

生成规则：

- `id` 使用日期加文件内容哈希短码，文件内容不变时 ID 稳定。
- `file` 始终使用相对路径和正斜杠，例如 `Reports/2027/example.html`。
- 日报按日期倒序、标题和路径稳定排序。
- 股票、大 V、行业和标签在单份日报内去重。
- `site.updatedAt` 使用最近日报日期，不使用构建时间。
- 输出 UTF-8、固定缩进和稳定字段顺序，避免无意义 Git 差异。
- 写入临时文件并通过校验后原子替换 `reports.json`。

现有手工整理的三条高质量元数据需要在首次迁移时保留。解析器支持 `data/report-overrides.json`，以文件路径为键覆盖自动结果；后续正常日报不需要维护该文件。

## 7. 首页与搜索

首页继续从 `reports.json` 计算并展示：

- 日报总数。
- 最近更新日期。
- 去重后的覆盖股票数。
- 去重后的大 V 数。

搜索索引继续覆盖：

- 标题和摘要。
- 日期与年份。
- 股票名称与代码。
- 大 V 名称。
- 标签、行业和来源。

自动导入只改变数据生产流程，不重写现有筛选、URL 参数和响应式页面结构。

## 8. 错误处理

错误分为阻断和警告两类。

阻断错误：

- 日期无法识别。
- HTML 无有效标题且文件名也无法生成标题。
- 两个文件生成重复 ID 或重复规范路径。
- 生成 JSON 不符合站点数据结构。

警告：

- 摘要使用默认文字。
- 未识别股票或大 V。
- 文件年份目录与解析日期年份不一致，并已自动迁移。
- 显式元数据中存在未知行业或标签。

本地脚本最终输出导入数量、归档路径、警告数量和测试结果，不输出日报正文。

## 9. 发布安全

`import_reports.ps1 -Publish` 在提交前执行以下检查：

- 当前目录必须是预期仓库。
- Git 工作区如果存在与导入无关的修改，则停止自动提交并提示人工处理。
- 只暂存 `Inbox/` 移动结果、`Reports/`、`reports.json`、词典和自动化相关文件。
- 提交信息使用日报日期范围生成，不包含正文内容。
- Git 推送沿用现有 `origin/master`。

默认不使用 `-Publish` 时只更新本地文件，便于预览和人工检查。

## 10. 扩展接口

解析器内部输出统一 `ReportRecord` 结构。未来功能只消费索引，不直接依赖 HTML 结构：

- 股票页面：按 `stocks[].code` 聚合日报。
- 大 V 页面：按 `influencers[]` 聚合观点。
- 标签页面：按 `tags[]` 聚合日报。
- 热门排行：使用预留的 `metrics` 和可选统计文件。
- 观点时间线：按日期、股票和大 V 组合过滤。
- 月度汇总：按年份和月份生成独立静态 JSON。

数据量较大后，可由生成器额外输出按年份拆分的索引；首页的数据访问层接口保持不变。

## 11. 测试与验收

自动测试至少覆盖：

- 三种日期来源和无法识别日期的失败路径。
- 标题、核心结论摘要和默认摘要解析。
- 表格、显式元数据、实体词典三种股票和大 V 识别方式。
- 标签、行业受控词表和去重上限。
- `Reports/<年份>/` 自动归档。
- 全量重建、稳定排序、稳定 ID 和原子写入。
- 保留现有三份日报及其首页搜索能力。
- 首页四项统计准确。
- 股票代码、名称、大 V、日期和标签搜索准确。
- GitHub Actions 对索引一致和不一致两种情况的行为。

验收场景：向 `Inbox/` 放入一份符合现有日报结构的新 HTML，运行一次 `import_reports.ps1` 后，文件进入正确年份目录，`reports.json` 出现对应记录，测试通过，本地首页可搜索到该日报；使用 `-Publish` 时可完成提交和推送，GitHub Pages 更新后线上可访问。

## 12. 非目标

- 不在本期加入数据库、后端 API、用户系统或在线编辑器。
- 不调用外部 AI 自动理解任意自由格式文档。
- 不承诺从完全无结构、无日期、无标题的任意 HTML 中准确提取全部实体。
- 不在本期实现股票详情页、大 V 详情页、热门排行或观点时间线，只保留稳定数据接口。
